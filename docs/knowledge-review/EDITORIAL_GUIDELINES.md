# Editorial Guidelines

## Overview

Editorial Guidelines ensure consistency, quality, and clarity across all Knowledge Packages.

## Writing Standards

### Voice and Tone

**Primary Voice:** Authoritative but approachable

- Expert but not condescending
- Clear but not simplistic
- Engaging but not distracting
- Professional but not stiff

**Tone Adjustments:**

- **Explanations:** Clear, patient, thorough
- **Activities:** Encouraging, supportive, challenging
- **Assessment:** Fair, constructive, specific
- **Reflection:** Thoughtful, personal, growth-oriented

### Language Guidelines

**Use:**

- Active voice
- Short sentences
- Common words
- Concrete examples
- Personal pronouns (you, we)

**Avoid:**

- Passive voice
- Long sentences
- Jargon without definition
- Abstract examples
- Third person (students, learners)

### Structure Guidelines

**Sections:**

- Clear headings and subheadings
- Logical flow
- Consistent formatting
- Visual hierarchy
- White space

**Paragraphs:**

- 3-5 sentences maximum
- One main idea per paragraph
- Topic sentence first
- Supporting details follow
- Transition to next paragraph

**Lists:**

- Parallel structure
- Consistent punctuation
- Logical ordering
- Appropriate length
- Clear purpose

## Content Standards

### Explanations

**Structure:**

1. What it is (definition)
2. Why it matters (relevance)
3. How it works (mechanism)
4. Examples (illustration)
5. Limitations (honesty)

**Quality Criteria:**

- Accurate
- Clear
- Complete
- Concise
- Relevant

### Activities

**Structure:**

1. Objective (what you'll learn)
2. Setup (what you need)
3. Steps (what to do)
4. Expected outcome (what should happen)
5. Reflection (what did you learn)

**Quality Criteria:**

- Engaging
- Achievable
- Relevant
- Challenging
- Rewarding

### Assessments

**Structure:**

1. Question (clear, specific)
2. Options (if multiple choice)
3. Correct answer
4. Explanation (why correct/incorrect)
5. Learning connection

**Quality Criteria:**

- Valid (measures what intended)
- Reliable (consistent results)
- Fair (accessible to all)
- Transparent (clear expectations)
- Constructive (promotes learning)

## Formatting Standards

### Headings

**Format:**

- H1: Knowledge Package title
- H2: Main sections
- H3: Subsections
- H4: Detailed divisions

**Rules:**

- Use sentence case
- Be specific and descriptive
- Maintain hierarchy
- Don't skip levels
- Keep parallel structure

### Code

**Format:**

- Use code blocks
- Include language specification
- Add comments for clarity
- Show expected output
- Include error handling

**Rules:**

- Test all code
- Use consistent style
- Include imports
- Handle edge cases
- Document assumptions

### Links

**Format:**

- Descriptive link text
- Open in new tab
- Check for broken links
- Use permanent links
- Document references

**Rules:**

- Link to primary sources
- Prefer official documentation
- Use stable URLs
- Archive important references
- Update regularly

### Images

**Format:**

- Alt text required
- Captions included
- Consistent style
- Appropriate size
- Accessible colors

**Rules:**

- Use original images when possible
- Credit sources
- Optimize for web
- Include diagrams for complex concepts
- Test accessibility

## Style Guide

### Terminology

**Consistent Usage:**

- Use the same term for the same concept
- Define technical terms on first use
- Provide alternatives for different audiences
- Maintain glossary
- Update terminology as field evolves

**Capitalization:**

- Title case for headings
- Sentence case for body text
- Lowercase for general concepts
- Uppercase for proper nouns
- Consistent throughout

### Numbers

**Rules:**

- Spell out one through nine
- Use numerals for 10 and above
- Use commas for thousands
- Use consistent units
- Include conversions when helpful

### Dates and Times

**Format:**

- Use ISO 8601 (YYYY-MM-DD)
- Use 12-hour time with AM/PM
- Include time zone when relevant
- Use relative dates when appropriate
- Be consistent throughout
