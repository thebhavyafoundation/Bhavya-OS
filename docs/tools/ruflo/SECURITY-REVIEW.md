# Ruflo — Security Review

**Reviewed:** 2026-11-12
**Reviewer:** OpenCode agent, against `AGENTS.md`, `PLATFORM-TRUTH.md` and the
constitutional dependency rules (02, 08).

---

## S1 — No unauthenticated remote MCP endpoint (material)

**Finding.** The MCP server listens on `0.0.0.0:3000` and is reachable on the
public `*.vercel.run` hostname. If it accepted unauthenticated calls, any party
that learned the URL could dispatch workers in the Foundation's account.

**Status: MITIGATED — enforced by the server, verified by test.**

Evidence:

```
POST /rpc  (no Authorization header)        -> 401 {"code":-32001,"message":"Unauthorized"}
POST /rpc  (Authorization: Bearer wrong)    -> 401 {"code":-32001,"message":"Unauthorized"}
GET  /health                                -> 200 {"status":"ok"}   (public by design, no data)
```

The token is auto-generated by Ruflo (64 chars), stored at
`/vercel/.claude-flow/mcp-http-token` with mode 0600, and is **never** written
to the repository. The agent reads it from a local secret file outside the repo
or from the sandbox, never from an argument list or a committed file.

## S2 — No paid API, no payment-method-requiring service

**Finding.** Ruflo's LLM execution path requires a provider credential.
`ANTHROPIC_API_KEY` and `OPENROUTER_API_KEY` are paid and are prohibited by
`PLATFORM-TRUTH.md`.

**Status: MITIGATED — free local model only.**

`OLLAMA_API_KEY=ollama` (a local placeholder, not a credential) with
`RUFLO_PROVIDER=ollama` and `qwen2.5:0.5b-instruct` running inside the remote
sandbox. No outbound call to any paid inference endpoint occurs.

## S3 — No production credentials in the sandbox

**Finding.** A sandbox with repository access could read secrets if they were
present in the clone or the environment.

**Status: MITIGATED.**

- The clone is of the **public** repository at a branch; no `.env` file is
  tracked and the CI secret-scan job enforces that no `.env` is committed.
- The sandbox environment contains no Cloudflare, Supabase, Turso or B2
  credential. `ruflo doctor` reported `API Keys: No API keys found`.
- No deployment credential is injected; the sandbox has no deploy capability for
  the production worker.

## S4 — Worker blast radius

**Finding.** `swarm_init` accepts `maxAgents` up to 50 and `agent_spawn` can
create many workers, each able to run `terminal_execute` commands.

**Status: MITIGATED — bounded by configuration and review.**

Every execution in this project used `maxAgents: 1` and a single task. The
acceptance gate (`scripts/ruflo/check-remote.sh`) is the only automation and it
creates exactly one swarm and one agent. Concurrency is increased only after
demonstrating value and safe ownership, with explicit human approval.

## S5 — Filesystem scope

**Finding.** `terminal_execute` runs shell commands in the sandbox.

**Status: ACCEPTED AND OBSERVED.**

Commands run as the sandbox user with `HOME=/vercel` and a working directory
under `/vercel/sandbox`. The sandbox is an isolated remote VM; it is not the
laptop and not the production host. The acceptance check asserts that **no
tracked application file is modified** after a write (`git status --porcelain`
shows only untracked artifacts). Verified: `modified_tracked=0`.

## S6 — Non-destructive first task

**Finding.** A first dispatched task must not deploy or alter external data.

**Status: MITIGATED.**

The first task was a read-only inspection of
`apps/ai-institute/src/components/curriculum/diagram/DiagramRenderer.tsx` that
wrote a findings file inside the sandbox clone. It performed no deployment, no
network write, and modified no tracked file. The acceptance check writes only
`ruflo-acceptance-report.md` inside the clone.

## S7 — Ruflo is not institutional authority

**Finding.** Ruflo's memory store is derived engineering context and could be
mistaken for a source of truth.

**Status: ACCEPTED AND DOCUMENTED.**

Ruflo memory is explicitly _derived_. GitHub and the approved project sources
remain authoritative. Ruflo's own README describes it as an orchestration layer,
not a replacement for GitHub, CI or application data stores. No Ruflo memory is
committed to the repository.

## S8 — Supply chain

**Finding.** `ruflo@3.76.0` pulls 617 packages, including packages with
install scripts (`better-sqlite3`, `argon2`, `onnxruntime-node`, `agentdb`).

**Status: ACCEPTED — remote, pinned, non-production.**

- The install happens only in the remote sandbox; no runtime dependency is added
  to the application, its lockfile or its bundle.
- The npm version is pinned exactly (`ruflo@3.76.0`); `latest` is never used.
- The upstream commit is recorded in `UPSTREAM-PIN.md`.
- No install script is executed on the control-centre laptop or on any
  developer workstation.

## S9 — MCP endpoint exposure during the working window

**Finding.** While the sandbox is running, its MCP endpoint is publicly routable
(protected by the bearer token, but still routable).

**Status: ACCEPTED — short-lived by design.**

The sandbox has a hard timeout (45 minutes on the Hobby plan). The endpoint stops
existing when the sandbox stops. A snapshot is taken for state recovery; the
snapshot is the durable artifact, not the live endpoint. For an extended
session the endpoint should be re-published from the snapshot rather than kept
alive indefinitely.
