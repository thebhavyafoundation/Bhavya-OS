# Validation Sprint — Bhavya Foundation

## Date: 2026-08-05

---

## The Problem

We produced 4 Knowledge Packages and scored them 10/10 ourselves.

**Nobody has actually used them.**

A 10/10 score means nothing if students can't learn from them. We've been measuring output ("How many KPs?") instead of impact ("How many people learned?").

**New KPI:** "How many people successfully learned from them?"

---

## Objective

Validate KP-001 through KP-004 with real learners. Collect evidence. Improve based on evidence. Only then resume production.

---

## Phase 1: Internal Validation (1-2 days)

**You are the first learner.**

Complete KP-001 → KP-004 exactly as a student would. Record everything.

### What to Record

| Category | Specific Items |
|----------|----------------|
| Confusing explanations | Which concepts were unclear? Where did you have to re-read? |
| Friction points | Where did you get stuck? What took too long? |
| Boring sections | Where did your attention wander? What felt repetitive? |
| Missing mentor guidance | Where did you wish you had help? What questions weren't answered? |
| Time taken | How long did each KP take? Was it reasonable? |
| Portfolio quality | Would you publish the project on GitHub? Is it impressive enough? |

### For Each KP, Complete

1. **Lesson** — Read through, do every "Try This" exercise
2. **Lab** — Follow the lab instructions exactly
3. **Project** — Build the project from scratch
4. **Assessment** — Take the assessment
5. **AI Mentor** — Interact with the mentor sequences

### Output

Fix every issue immediately. Update the KP files.

## Phase 2: Pilot Cohort (5-10 learners)

### Recruit

| Learner Type | Count | Why |
|-------------|-------|-----|
| Complete beginners | 2 | Can they follow along with no prior knowledge? |
| College students | 3 | Are they engaged? Is it relevant to their studies? |
| Developers | 2 | Is the technical content accurate? Is it too basic? |
| Working professionals | 2 | Is it practical? Would they use this at work? |
| Educator | 1 | Is the pedagogy sound? Would they recommend it? |

### How to Recruit

- Ask friends, family, colleagues
- Post on LinkedIn: "Looking for 5-10 people to test our free digital literacy curriculum"
- Offer: Free lifetime access to all KPs + certificate of completion
- Requirements: Complete all 4 KPs in 2 weeks

### What to Measure

| Metric | How to Measure |
|--------|----------------|
| Completion rate | What percentage finished all 4 KPs? |
| Time to complete | How long did each KP take? |
| Questions asked | What did learners ask about? |
| Drop-off points | Where did learners stop? |
| Confidence before/after | Survey: "How confident are you with computers?" (1-10) |
| Portfolio outcomes | Did they publish their projects? |

### Observation Protocol

- Don't explain anything. Let them struggle.
- Watch silently. Take notes.
- Only help if they ask.
- Record their exact words when they're confused.
- Note what they enjoy. Note what they skip.

### Tools

- Screen recording (with permission)
- Google Form for pre/post surveys
- WhatsApp group for questions
- GitHub for portfolio tracking

## Phase 3: Improve (Based on Evidence)

Only after collecting evidence:

### For Each KP

1. What confused learners? → Rewrite those sections
2. Where did they drop off? → Make those sections more engaging
3. What did they skip? → Remove or improve
4. What did they love? → Do more of that
5. What was too hard? → Add more scaffolding
6. What was too easy? → Add challenges

### Specific Improvements

| Issue | Fix |
|-------|-----|
| Confusing explanation | Rewrite with simpler language, more examples |
| Friction point | Add step-by-step screenshots, video walkthrough |
| Boring section | Add interactive elements, real-world relevance |
| Missing guidance | Expand AI Mentor, add hints |
| Too long | Break into smaller chunks |
| Too short | Add depth, extension activities |
| Portfolio not impressive | Improve project scope, add real-world applications |

---

## Phase 4: Scale (Only After Validation)

### Criteria for Scaling

Before producing KP-005 onward, ALL of these must be true:

- [ ] Completion rate ≥ 80%
- [ ] Average confidence improvement ≥ 3 points (1-10 scale)
- [ ] At least 50% of learners publish their projects
- [ ] Average time per KP is reasonable (2-4 hours)
- [ ] No major confusion points remain
- [ ] Educator validates pedagogy

### If Criteria Not Met

Go back to Phase 3. Improve more. Re-test with new learners.

### If Criteria Met

Produce KP-005 through KP-010 using the validated standard.
