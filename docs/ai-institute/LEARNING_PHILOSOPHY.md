# Learning Philosophy

Bhavya Institute's teaching principles. Every lesson, lab, assessment, and interaction reinforces these.

---

## 1. Learn by Building

**Principle:** Understanding comes from construction, not consumption.

**Application:**

- Every concept is applied in a lab within the same lesson
- Students build real systems from day one
- Theory is always paired with practice
- "I built this" replaces "I watched this"

**Example:**

- Lesson: "What is an API?" → Lab: "Build an API that returns weather data"
- Lesson: "What is a prompt?" → Challenge: "Write 10 prompts for different tasks"

---

## 2. AI-First

**Principle:** AI is the learning environment, not just the subject.

**Application:**

- Students interact with AI mentors throughout
- AI assists but doesn't complete work
- Students learn to work with AI, not just about AI
- The platform itself uses AI for personalization

**Example:**

- AI mentor provides hints, not answers
- AI evaluates code and suggests improvements
- AI generates personalized practice challenges
- AI explains why something is wrong, not just that it's wrong

---

## 3. Open Source First

**Principle:** Learning materials should be open, contributable, and transparent.

**Application:**

- All curriculum is open source
- Students contribute to real repositories
- Learning materials version-controlled
- Community can improve content

**Example:**

- Students submit PRs to improve lessons
- Lab starter projects are open source repos
- Curriculum changes are transparent
- Community reviews content improvements

---

## 4. Research-Backed

**Principle:** Every educational decision traces to evidence.

**Application:**

- Spaced repetition for retention
- Retrieval practice over re-reading
- Interleaving topics for transfer
- Dual coding (visual + verbal)
- Concrete examples before abstract concepts

**Example:**

- Knowledge checks use spaced repetition
- Labs build on previous concepts
- Assessments mix problem types
- Lessons use diagrams alongside text

---

## 5. Project-Driven

**Principle:** Assessments are real projects, not artificial quizzes.

**Application:**

- Every module ends with a project
- Projects solve real problems
- Portfolio is the primary credential
- Peer review builds community

**Example:**

- Module 1 project: "Build a chatbot that answers questions about a repository"
- Module 2 project: "Automate a workflow using AI"
- Capstone: "Build and deploy an AI-powered tool"

---

## 6. Community Learning

**Principle:** Students learn faster together.

**Application:**

- Study groups form naturally
- Peer teaching reinforces understanding
- Discussion forums for questions
- Collaborative projects

**Example:**

- Students explain concepts to each other
- Code review circles
- Pair programming sessions
- Study groups meet weekly

---

## 7. Mentor-Guided

**Principle:** Human experts accelerate learning beyond what solo study achieves.

**Application:**

- Every student has a mentor
- Mentors provide career guidance
- Mentors review projects
- Mentors model expert thinking

**Example:**

- Weekly office hours
- Project reviews with feedback
- Career path discussions
- Industry perspective sharing

---

## 8. Continuous Practice

**Principle:** Learning is not an event but a process.

**Application:**

- Daily challenges maintain skills
- Spaced repetition reinforces memory
- Progressive difficulty builds competence
- Long-term projects develop depth

**Example:**

- Daily prompt challenges
- Weekly coding challenges
- Monthly project milestones
- Quarterly capstone presentations

---

## 9. Knowledge Package First

**Principle:** Every piece of content is a reusable, atomic unit.

**Application:**

- Lessons are Knowledge Packages
- Labs are Knowledge Packages
- Assessments are Knowledge Packages
- Everything links to other packages

**Example:**

- A lesson on "API Design" links to knowledge about REST, HTTP, and databases
- A lab on "Prompt Engineering" links to knowledge about LLMs and tokenization
- An assessment on "Architecture" links to knowledge about patterns and ADRs

---

## 10. Teach Before Automating

**Principle:** Understanding precedes automation.

**Application:**

- Students build things manually first
- Then learn to automate
- Then learn to scale
- Automation is a reward for understanding

**Example:**

- Write prompts manually → then build prompt templates
- Test manually → then write automated tests
- Deploy manually → then set up CI/CD

---

## Measuring Philosophy Adherence

Every lesson is evaluated against these principles:

| Principle          | Question                                       | Score |
| ------------------ | ---------------------------------------------- | ----- |
| Learn by Building  | Does the student build something?              | /5    |
| AI-First           | Does the student interact with AI?             | /5    |
| Open Source        | Is the content open and contributable?         | /5    |
| Research-Backed    | Is there evidence for the approach?            | /5    |
| Project-Driven     | Does it lead to a real project?                | /5    |
| Community          | Does it encourage collaboration?               | /5    |
| Mentor-Guided      | Does it support mentor interaction?            | /5    |
| Continuous         | Does it reinforce previous learning?           | /5    |
| Knowledge Packages | Is it a reusable unit?                         | /5    |
| Teach First        | Does it build understanding before automation? | /5    |

**Minimum score:** 35/50 for any content to be published.
