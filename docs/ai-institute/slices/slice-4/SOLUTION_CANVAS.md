# Solution Canvas

## Overview

The Solution Canvas defines the solution before building. It captures the problem, users, goals, constraints, and design decisions.

## Canvas Components

### Problem

One sentence: What problem are you solving?

### Users

Who will benefit from this solution?

### Goals

What will this solution achieve? (one per line)

### Non-Goals

What will this solution NOT do? (one per line)

### Constraints

What are the limitations? (one per line)

### Risks

What could go wrong? (one per line)

### AI Opportunities

How can AI help solve this? (one per line)

### Ethics

What ethical considerations exist? (one per line)

### Success Metrics

How will you measure success? (one per line)

## Design Decisions

For every key decision, document:

- **Question**: What are you deciding?
- **Decision**: What did you decide?
- **Rationale**: Why is this the best approach?
- **Alternatives**: What other options existed?
- **Knowledge Package References**: What resources informed this decision?

## Why Canvas Before Code

### Traditional Approach

Students jump into coding without understanding the problem.

### Bhavya Approach

Students define the solution before building. This ensures:

- Clear understanding of the problem
- Informed design decisions
- Evidence-based building
- Documented rationale
