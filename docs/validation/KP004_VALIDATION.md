# KP-004 Validation Report: Software Installation

## Date: 2026-08-05

---

## Beginner Walkthrough

### Time Spent
- Lesson: ~2 hours (as designed)
- Project: ~45 minutes (as designed)
- Assessment: ~45 minutes
- Lab: ~30 minutes
- **Total: ~4 hours direct engagement**

### Confusing Concepts
1. **System vs. Application Software** — The cooking analogy (OS = kitchen, apps = tools) helps, but the boundary is blurry (antivirus, file manager).
2. **Installation Process (6 Steps)** — Extraction, File Placement, Configuration, Dependencies, Shortcut Creation, Registration. This is technically accurate but may be too detailed for beginners.
3. **Dependencies** — The concept that "your program needs other programs to work" is confusing for students who have never thought about software dependencies.
4. **DLL Errors** — The MSVCP140.dll error in the assessment is technically accurate but may be too advanced for Grade 9.
5. **Least Privilege** — The concept is important but the explanation may be too abstract.

### Questions Asked
1. "How do I know if a download is safe?" (addressed in Section 2)
2. "Why can't I just download from any website?" (addressed in Section 2)
3. "What is bundled software?" (addressed in Section 3)
4. "Why are updates so important?" (addressed in Section 5)
5. "How do I uninstall software properly?" (addressed in Section 6)
6. "What happens during installation?" (addressed in Section 3)
7. "Why does this app want my camera?" (addressed in Section 4)

### Points of Friction
1. **Source Verification Checklist** — 5 steps is a lot to remember. Students may skip steps.
2. **Installation Process (6 Steps)** — The detailed breakdown is technically accurate but may overwhelm beginners who just want to install software.
3. **Permissions Audit** — The exercise asks students to evaluate each permission. This requires understanding what each permission means, which beginners may not have.
4. **WannaCry Story** — While compelling, it's a tangent from the installation process. May distract from core learning.
5. **Lab 3 (Install Software)** — The lab requires actually installing software, which may not be possible on school computers with restrictions.

### Moments of Excitement
1. **"Paperweight Experiment"** — The opening is powerful. "Without software, the most powerful computer in the world is an expensive paperweight."
2. **"Sort the Software"** — Sorting programs into system vs. application categories is engaging and practical.
3. **"Source Investigation"** — Investigating whether a download source is safe is immediately relevant.
4. **"Fake Site Challenge"** — Finding "free Photoshop" sites is eye-opening and memorable.
5. **"Red Flag Test"** — The calculator app asking for camera access is a powerful illustration of least privilege.
6. **WannaCry Story** — The real-world consequence of not updating is compelling.

### Drop-off Risk
1. **Section 3 (Installation Process)** — The6-step technical breakdown may lose non-technical students.
2. **Section 4 (Permissions Audit)** — Requires understanding of what each permission means.
3. **Lab 3 (Install Software)** — May not be possible on restricted school computers.

### Confidence
- Before: 2/10 (most students install software without thinking)
- After: 5/10 (can verify sources, understand installation process, manage permissions)

### Skills Gained
- System vs. application software distinction
- Source verification (5-step checklist)
- Installation process understanding
- Permission management (least privilege)
- Update management
- Proper uninstallation

### Portfolio Value
The project produces a professional-grade installation guide with comparison table, security checklist, and troubleshooting. **Score: 8/10.**
