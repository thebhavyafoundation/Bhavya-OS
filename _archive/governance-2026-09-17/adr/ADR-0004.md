# ADR-0004 — APP-003 Enhancement Roadmap & Development Discipline

## Status

Accepted

## Context

APP-003 Admin Platform v0.1.0 is complete with dashboard, content management, release management, audit log, and user/role management. The platform is at v1.0.0-rc2 awaiting external validation (staging, UAT, operational rehearsal).

The temptation exists to immediately build more apps or implement complex features (auth, RBAC, CRUD workflows). However, these features increase operational complexity and should only be implemented after real operational needs are confirmed through staging and daily use.

## Decision

We adopt the following development discipline:

### Enhancement Priority (Post-Staging)

1. **Registry-backed Content Editing**
   - Schema validation against existing JSON schemas
   - Draft/publish workflow (not direct JSON editing)
   - Automatic metadata updates (updated dates, versions)
   - Version history with diff view
   - Preview before publish

2. **Authentication Integration**
   - Modular interface (not coupled to specific provider)
   - Support for future identity providers
   - Placeholder implementation until real provider configured
   - Design behind an interface for swappability

3. **Audit Expansion**
   - Capture: document published, policy updated, release created, content archived
   - Structured audit entries with actor, action, target, timestamp
   - Searchable, filterable audit trail

4. **Operational Dashboard**
   - Application health from runtime endpoints
   - Runtime metrics (uptime, request counts)
   - Backup status and latest snapshot info
   - Release version and deployment history
   - Single-pane operational control center

### Development Discipline

- **Feature freeze after v1.0.0 GA**: Only maintenance work on the release branch
- **Patch releases (X.Y.Z+1)**: Bugfixes, security patches
- **Minor releases (X.Y+1.0)**: New capabilities
- **Major releases (X+1.0.0)**: Significant architectural evolution only
- **No new apps until operational needs justify them**

### What We Will NOT Build (Until Needed)

- APP-004, APP-005, APP-006 — only if operational needs emerge
- Real authentication — until identity provider is configured
- Complex CRUD workflows — until content editing patterns are validated
- RBAC — until user roles are tested in practice

## Alternatives Considered

- **Build all apps immediately**: Rejected because it adds complexity without validated need
- **Implement auth now**: Rejected because no identity provider is configured
- **Skip staging validation**: Rejected because operational readiness must be confirmed

## Consequences

**Benefits:**

- Focus shifts from building to using the platform
- Engineering driven by real operational needs
- Platform stability maintained through disciplined releases

**Trade-offs:**

- Delays some features until after GA
- Requires patience during external validation phase

**Future Implications:**

- All new features must be justified by operational need
- Enhancement roadmap reviewed quarterly
- ADR required for any major architectural change
