# ADR-0002 — Provider-Agnostic AI Gateway Abstraction Layer

## Status

Accepted

## Context

Bhavya OS relies on artificial intelligence engines (such as Claude Code, OpenHuman, and internal background workers) for code generation, decision support, summarization, research, and voice transcription. Direct coupling of platform applications to specific vendor APIs (e.g., Anthropic, OpenAI, or NVIDIA NIM) creates vendor lock-in, introduces security risks, and makes long-term maintenance fragile.

To ensure institutional longevity and flexibility, Bhavya OS requires a unified, provider-agnostic AI Gateway.

## Decision

We adopt a provider-agnostic AI Gateway architecture. All application and agent model interactions MUST route through the AI Gateway abstraction layer.

### Stable Gateway Interface Contract

The gateway exposes a single stable interface contract:

1. `generate()` — Text/content generation and tool use.
2. `chat()` — Multi-turn conversation streaming.
3. `embed()` — Vector embeddings for semantic search/RAG.
4. `transcribe()` — Speech-to-text audio processing.
5. `reason()` — Deep reasoning and chain-of-thought execution.

### Backends

Providers (NVIDIA NIM, OpenRouter, DeepSeek, LM Studio, Ollama, llama.cpp) are pluggable backends hidden behind this interface. Changing or swapping an AI model or vendor requires zero changes to application code in Bhavya OS.

## Alternatives Considered

- **Direct SDK Integration per App**: Rejected because every app would duplicate API key handling, error handling, and model-specific formatting.
- **Single Vendor Mandate**: Rejected because model availability, rate limits, pricing, and performance shift rapidly across providers.

## Consequences

- **Benefits**: Complete vendor neutrality, automatic failover, centralized rate limiting, unified audit logging.
- **Trade-offs**: Requires maintaining translation layer mappings for provider-specific capabilities.
