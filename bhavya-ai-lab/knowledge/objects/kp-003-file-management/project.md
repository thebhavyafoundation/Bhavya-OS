# Project: File Organization System

**Grade:** 9 | **Duration:** 45 minutes | **Type:** Project-based learning

---

## Project Overview

Design and implement a complete file organization system for a realistic school scenario. You will create folder structures, establish naming conventions, organize existing files, and document your system so thoroughly that a stranger could follow it.

This is not a worksheet exercise. This is a **portfolio piece** — something you can show to future teachers, employers, or college admissions as evidence of your digital literacy skills.

### The Scenario

You are the newly appointed "Digital Organization Lead" for your school's science club. The club has been running for three years, but files are scattered across different computers, USB drives, and email attachments. The club advisor has asked you to create a proper file management system that any club member can follow.

### Learning Objectives
- Design a hierarchical folder structure that serves multiple users and purposes
- Apply consistent file naming conventions across different file types
- Organize messy, unstructured files into a clean system
- Document the system so new members can follow it
- Present your work in a format ready for GitHub or a portfolio

---

## Deliverables

### 1. Folder Structure Design (10 minutes)

Design a folder structure that accommodates:
- Meeting notes and agendas
- Project files (at least 3 different projects)
- Photos and media from events
- Administrative documents (membership lists, budgets, contacts)
- Resources and reference materials

**Requirements:**
- At least 3 levels of hierarchy in at least one branch
- At least 8 folders total
- Logical grouping that makes sense to someone who did not design it
- A clear rationale for every design decision

**Design Template:**
```
Science-Club-Files/
├── [Folder 1]
│   ├── [Subfolder 1A]
│   └── [Subfolder 1B]
├── [Folder 2]
│   └── [Subfolder 2A]
├── [Folder 3]
└── [Add more as needed]
```

**Write your complete design in `project-folder-design.txt`.**

---

### 2. Naming Convention Guide (10 minutes)

Create a naming convention guide that the club will adopt. Your guide must include:

**Required Elements:**
1. Date format (explain your choice and why YYYY-MM-DD sorts correctly)
2. File name structure (show the pattern with placeholders)
3. At least 5 examples for different file types (meeting notes, photos, reports, presentations, budgets)
4. A list of forbidden characters and why they are forbidden
5. Version naming rules (how to handle drafts and revisions — when to use v1, v2, draft, final)
6. Edge cases (what do you do when a file name is too long? When two files have the same name?)

**Template:**
```
SCIENCE CLUB FILE NAMING GUIDE

Date Format: [Your format]
File Name Pattern: [Your pattern]

Examples:
- Meeting notes: [example]
- Project files: [example]
- Photos: [example]
- Presentations: [example]
- Budgets: [example]

Forbidden Characters: [list and reasons]

Version Naming: [your rules]

Edge Cases: [how you handle unusual situations]
```

**Write your complete guide in `project-naming-guide.txt`.**

---

### 3. File Organization (15 minutes)

Using your folder design and naming guide, organize these messy files:

**The Mess (files with bad names in a flat folder):**

```
untitled.docx
photo_2024_03_15.png
meeting notes march.txt
budget.xlsx
IMG_4521.jpg
science fair.docx
notes.txt
presentation final FINAL v2.pptx
member list.csv
report draft.docx
screen shot 2026-01-20.png
ideas.txt
```

**Instructions:**
1. Create your folder structure on your computer
2. Rename each file following your naming guide
3. Move each file to its correct folder
4. Delete any files that are truly empty or useless (check each one first)

**Expected Result:**
- All 12 files renamed and placed in correct folders
- No files left in the original flat folder
- File names follow your naming guide exactly

---

### 4. Documentation — GitHub-Ready README (10 minutes)

Write a `README.md` that explains the system to a new club member who has never seen it before. This should be formatted like a professional GitHub repository README.

**Required Sections:**

```markdown
# Science Club File Management System

## Overview
[What is this system for? Who is it for?]

## How to Navigate
[Quick guide to finding things — include the folder tree]

## Naming Conventions
[Summary of the naming rules with examples]

## How to Add New Files
[Step-by-step instructions for adding new work]

## Rules
[What club members must and must not do]

## How I Organized My Files
[Reflection: explain your design decisions. Why did you choose this 
structure over alternatives? What tradeoffs did you consider?]

## Before and After
[Show the messy state vs. your organized state]
```

**Write your documentation in `project-readme.md`.**

### 5. Presentation and Reflection (bonus — 5 minutes)

Prepare a 2-minute verbal explanation of your system. You will explain:
- Why you chose your folder structure
- What makes your naming convention effective
- One mistake you made and how you fixed it
- What you would do differently if you started over

## Portfolio Requirements

This project is designed to be **portfolio-ready**. When you finish, your work should be:

1. **GitHub-compatible** — The README.md uses proper markdown formatting
2. **Screenshot-worthy** — Your folder structure looks clean in screenshots
3. **Presentable** — You can explain your system in 2 minutes without reading notes
4. **Documented** — Every design decision has a reason
5. **Before/After** — The transformation is visible and dramatic

### How to Present This Project

**For your portfolio:**
- Take a screenshot of your organized folder structure
- Include the before/after comparison in your README
- Write the "How I Organized My Files" reflection thoughtfully
- Link to your naming convention guide as a separate document

**For a presentation:**
- Start with the "before" state (the messy files)
- Walk through your design decisions
- Show the "after" state
- Explain one thing you would improve

## Extension Activities

### For Students Who Finish Early

1. **Create a Folder Template** — Package your folder structure as a template that can be duplicated for new projects. Write a script or step-by-step guide for creating it automatically.

2. **Design a Backup Plan** — Write a one-page backup strategy for the club using the 3-2-1 rule. Include specific services, schedules, and responsibilities.

3. **Peer Review** — Swap your system with a classmate. Using only their documentation (not their verbal explanation), try to add a file to the correct folder. Report back what was clear and what was confusing.

4. **Stress Test** — Ask a teacher or parent to try using your system for 5 minutes. Watch them without helping. Note where they hesitate or get confused. Redesign based on what you observe.

5. **Digital vs Physical** — Compare your digital file organization to how the club organizes physical materials (binders, posters, equipment). What similarities and differences do you notice?

## Real-World Connections

This project mirrors how professional organizations manage files:
- **Software companies** use folder structures with `src/`, `docs/`, `tests/`, `build/` directories — and every project has a README.md
- **Design agencies** organize by client, then by project, then by asset type — and document their system for new team members
- **Research labs** use date-based and project-based organization — and name files with strict conventions for reproducibility
- **Schools and universities** organize by department, course, then semester — and create guides for students

The skills you practice here apply directly to future careers in any field that uses computers. The ability to organize, document, and present a file system is a professional skill that most people never learn.
