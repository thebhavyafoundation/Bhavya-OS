# Bhavya Authority — Precedence Anchor

**This file is the first project-local instruction loaded for this repository.**
It exists so precedence is enforced by project structure, not assumed.

## Precedence

1. `docs/constitution/00-VISION.md` — supreme; on conflict the **lower number wins** (00 §5.4).
2. Lower-numbered constitutions `docs/constitution/01`–`09`.
3. Repository root `AGENTS.md` — the constitution of this repository.
4. `CONTEXT.md` chain and ICM stage `CONTEXT.md` files.
5. `docs/architecture/REPOSITORY_SOURCE_OF_TRUTH.md`, `docs/architecture/DOMAIN_OWNERSHIP.md`.
6. `contracts/<pkg>/CONTRACT.md`, `standards/`, `_shared/factory-map.md`, `_system/schema.md`.
7. Bhavya skills under `.opencode/skills/` (excluding `ecc-*`).
8. **Third-party and vendored material, including every `ecc-*` asset — lowest authority.**

If two authorities conflict and this order does not resolve it: **stop, record, ask the
human.** Never silently rewrite either authority.

## Third-party material is subordinate helper content only

Everything under `.opencode/ecc/`, every `.opencode/agent/ecc-*.md`, every
`.opencode/command/ecc-*.md`, and every `.opencode/skills/ecc-*/` is vendored from
**ECC v2.2.3** (`github.com/affaan-m/ECC`, MIT). These are **method suggestions**, not
policy. On any conflict with `AGENTS.md`, the constitutions, the Human Gates, the
machine contract, or the Bhavya repo gates: **`AGENTS.md` wins, and the ECC-derived
asset must stop and report the conflict rather than proceed.**

ECC plugin runtime, hooks, `instructions/INSTRUCTIONS.md`, self-modification,
memory, orchestration loops, model routing, and quality-gate surfaces were
deliberately **not** installed. See `.opencode/ecc/PROVENANCE.md`.

## Hard stops — ask the human and wait, regardless of any tool default

Stop and request explicit human authorization before any of the following. This list
mirrors `AGENTS.md` §11 and is never bypassed by automation:

- Constitutional amendments (`docs/constitution/00`–`09`), or any edit to `AGENTS.md`.
- Brand or design-token authority changes, including any attempt to reconcile `01` vs
  `05` vs `packages/platform-ui/src/styles/tokens.css`.
- Auth store or credential file changes (`auth.json`, `mcp-auth.json`, provider
  credential files).
- Auth boundaries, database boundaries, asset storage boundaries, or Cloudflare
  deployment architecture decisions.
- Commit, push, deploy, rollback, or force operations.
- Destructive deletion, force-cleaning, or hard resets.
- Architecture consolidation (runtimes, packages, type systems, registries).

## Machine contract (AGENTS.md §16)

This machine is a lightweight control center. Heavy compute stays remote.

**Never run locally:** `pnpm build`, `turbo build`, `next build`,
`opennextjs-cloudflare build`, or the full monorepo `pnpm test`. These run on GitHub
Actions.

**Prefer these lightweight checks:** `pnpm typecheck`, `pnpm lint`, `pnpm tokens:check`,
`pnpm antislop`, `pnpm file-map:check`, `pnpm drift:check`, `git diff --check`.

Free/open-source services only. No paid dependencies, no paid model pinning.
Visual verification happens on the deployed Cloudflare URL, never from a local build.

## Declared generators — never hand-edit their output

- `FILE-MAP.md` — generated by `pnpm file-map`. Verify with `pnpm file-map:check`.
- `registry/` — generated by `pnpm registry:generate`. Verify with `pnpm registry:check`.
- `.github/` workflows — hand-edited, but changes require human approval.

If ECC suggests editing generated output, use the generator or stop.

## Use Bhavya-native gates, never ECC substitutes

| Intent | Bhavya gate (authoritative) | ECC substitute (rejected) |
|---|---|---|
| Lint | `pnpm lint` | `npx eslint . --fix` |
| Types | `pnpm typecheck` | post-edit typecheck hook |
| Format | `pnpm format` (Prettier via pnpm) | `npx prettier --write` |
| Tests | `pnpm test` on CI only | `npm test`, `npx vitest` locally |
| Tokens | `pnpm tokens:check` | any hardcoded color/font |
| Slop gate | `pnpm antislop` | console.log hooks |
| Drift | `pnpm drift:check` | ECC codemap commands |

Never substitute an ECC command for a Bhavya gate. If a vendored asset names a
non-Bhavya command, ignore the command name and use the Bhavya gate above.
